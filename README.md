# パズルルート

パズル画面をリアルタイムで読み取り、盤面を認識して、**指で動かすルートを矢印で表示する補助アプリ**です。

- iPhone アプリ（画面共有で盤面を読み取る）＋ **PC ビューアー**（PC のブラウザに矢印を大きく表示）
- **iPhone だけで使う場合**は、盤面とルートの図を**小窓（ピクチャ・イン・ピクチャ）**に表示できます（試験中の機能です。下の「iPhone だけで使う（小窓）」を参照）。iOS ではゲーム画面に直接矢印を重ねることはできないため、小窓を盤面に重ならない位置に置いて使います
- Android 版（`android` フォルダ）は、盤面の上に直接矢印を重ねて表示します

> 画面共有はユーザーが開始した場合だけ動作します。画面は端末内または同一ネットワーク内で処理されます。本アプリは操作を自動実行しません。利用するサービスの規約を確認したうえで使用してください。

---

## このアプリがしないこと（大切）

- **自動でタップ・スワイプしません。** 実際の操作は必ずあなた自身が指で行います
- マクロ、タッチの自動入力、ほかのアプリの改変、メモリの読み取り、通信の改変はしません
- 脱獄や非公開の仕組みは使いません。画面の読み取りは Apple 公式の **ReplayKit（画面共有）** だけを使います
- 画面共有はあなたが iOS 標準の確認画面で開始したときだけ動きます（勝手に始まりません）
- 画面の画像は**保存しません・PC にも送りません**。PC に送るのは「盤面の認識結果とルート」だけです
- 外部のクラウドには何も送りません。通信は同じ Wi-Fi（同一ネットワーク）の中だけです

## 1. PC ビューアーの起動方法

1. GitHub のこのリポジトリで「**Actions**」→「**PC ビューアー ビルド**」を開き、いちばん新しい実行（緑のチェック）をクリック
2. 下の「Artifacts」にある **PuzzleRoute-Viewer** をダウンロードして解凍
3. 起動する
   - **Windows**：`起動_Windows.bat` をダブルクリック
     - 「Windows によって PC が保護されました」と出たら「詳細情報」→「実行」
     - 「Windows セキュリティの重要な警告」が出たら「**プライベート ネットワーク**」にチェックして「アクセスを許可する」
   - **Mac**：`起動_Mac.command` を**右クリック →「開く」→「開く」**
     - 「受信接続を許可しますか？」と出たら「許可」
4. 自動でブラウザ（Chrome / Edge）が開き、QR コードが表示されます
   - 開かないときは、ブラウザで `http://127.0.0.1:48123/` を開いてください
   - この画面は**起動した PC でしか開けません**（ほかの端末からは見られません）

終了するときは、起動時に開いた黒い（または白い）ウィンドウを閉じます。

## 2. iPhone と PC を同じ Wi-Fi へ接続する

- iPhone：設定アプリ →「Wi-Fi」で、PC と**同じ名前の Wi-Fi** を選びます
- PC：画面右下（Windows）／右上（Mac）の Wi-Fi マークから同じ Wi-Fi を選びます
- 有線 LAN の PC でも、同じルーターにつながっていれば使えます
- ホテルやカフェなどの公衆 Wi-Fi では、端末どうしの通信が禁止されていて使えないことがあります

## 3. QR コードで接続

1. iPhone で「パズルルート」を開き、「**QR コードで接続**」を押す
2. 初回はカメラの許可と「ローカルネットワーク」の許可を求められるので「許可」
3. PC の画面の QR コードを読み取る → 「PC と接続しました」と出れば完了

QR が読めないときは「**同じ Wi-Fi の PC を探す**」を押し、見つかった PC を選んで、PC 画面の **6 桁の接続コード**を入力します。

- QR とコードは 10 分で作り直されます（PC 画面に残り時間が出ます）
- 接続するたびに新しい「接続トークン」が発行され、前のものは使えなくなります
- PC 画面の「**切断**」、または iPhone の「PC との接続を切る」でいつでも切断できます

## 4. iPhone で画面共有を開始する

1. アプリの「**画面共有を開始**」を押す
2. iOS の確認画面で「**パズルルート**」を選び、「**ブロードキャストを開始**」を押す
3. 3 秒のカウントのあと、画面上部が赤く（または赤い丸が）表示されます。これが画面共有中の目印です
4. ゲームを開いてパズル画面を表示すると、盤面が止まったところで自動的にルートが計算され、PC に表示されます

PC ビューアーの見方：

- 上の帯：**つかむ場所**（何段目・何列目）と、最初の数手の矢印
- 盤面：緑の輪＝つかむドロップ、線と番号＝なぞる順番、白い四角「終」＝指を離す位置
- 矢印は手順ごとに色が変わり、番号付きなので、ルートが交差しても順番が分かります
- 「再生」「1手進む」「1手戻る」「最初に戻る」で順番を確認できます。速さ・矢印の太さ・色も変えられます
- 「全画面」や、PC のブラウザ（Chrome / Edge）の「小窓で手前に表示」も使えます（これは PC 側だけの機能です）
- 黄色い枠は認識に自信がないマスです。**マスをクリックして色を直す**と、PC で自動的に探し直します

ルートは、**表示された後はドロップを動かしている間も変わりません**（途中で指を止めても、別のルートに切り替わりません）。コンボで消えて次の盤面になると、自動で計算し直します。ドロップを動かしたのにコンボが出なかったときなどは、iPhone アプリの「今の画面で計算し直す」を押してください。

ルートは、**盤面の色の数から決まる最大コンボ数**（同じ色3個で1コンボとして数えた上限）に届くまで探します。届いたときは「最大◯コンボに到達」、時間内に届かなかったときは「この盤面の最大は◯コンボ」と表示します。最大コンボには平均で25〜30手ほど必要なので、「手数の上限」は 48 手（32 / 48 / 64 から選べます）が初期値です。届かない盤面が多いときは「探索時間」を長くしてください。

表示されるのは「**見つかった候補**」です（最大コンボに届かない盤面もあります）。盤面の外から降ってくるドロップ、スキルによるコンボ加算、ダメージは計算しません。

## iPhone だけで使う（小窓）

1. アプリで「画面共有を開始」してから、画面下の「**小窓で表示**」を押す（小窓の開始は必ずこのボタンから行います）
2. 小窓が表示されたことを確認してからゲームへ切り替えます。小窓はドラッグで動かせるので、**パズルの盤面に重ならない画面の上のほう**へ置きます
3. 小窓を大きくするには、ピンチ（2本指で広げる）します
4. 閉じるときは小窓の × か、アプリの「小窓を閉じる」

うまく出ないときは、画面下のバーの「ⓘ」で診断（PiP対応・開始可能・実行中・最後のエラー・開始できない理由）を確認できます。

> 小窓の中身は、シミュレーター（テスト用の仮想 iPhone）では確認できません（Apple のシミュレーターが小窓に対応していないため）。実機で表示を確認するまでは「試験中」の機能です。
> 小窓を使うため、アプリは「音声（バックグラウンド）」の設定をしていますが、音は鳴らさず、ゲームの音も止めません。

## 敵の妨害（縛り）があるとき

敵のスキルでパズルが縛られたときは、iPhone アプリの盤面の下にある「マスを押したとき」でボタンを選んでから、盤面のマスを押します（もう一度押すと外れます）。設定した縛りはルートの計算に使われ、PC ビューアーで探し直すときも守られます。

| ボタン | こんなとき | ルートの計算 |
|---|---|---|
| 開始位置 | 盤面にカーソルが出て、そこから動かし始めるよう指定された（操作位置固定） | 必ずそのマスから動かし始める |
| 操作不可 | テープ・お札が貼られたマス | そのマスは動かさず、指で通らない |
| 棘 | 動かすとダメージを受ける棘ドロップ | そのマスを通らない |
| 雲・ルーレット | 雲で見えない、色が変わり続けるマス | 消えないものとして計算する（動かすことはできる） |

×印が付いて「消せない状態」になったドロップは、「敵の妨害（縛り）」の「消せない状態のドロップ」で種類を選びます。消えないものとして計算し、最大コンボの数からも除きます。

縛りは「縛りをすべて解除」を押すまで続きます。敵の効果が切れたら解除してください。いまのところ縛りは自動では読み取らないので、手で設定してください。

## 読み間違いを直す

黄色い枠のマスは、認識に自信がないマスです。マスを押して正しいドロップを選ぶと、見た目が近いほかのマスもまとめて直ります。直した色はこの iPhone の中だけに覚えられ、次の盤面からは同じ見た目のドロップを正しく読みます。

## 5. 画面共有を終了する

- 画面上部の赤い表示（または時計の部分）をタップ →「停止」
- またはコントロールセンターの画面収録ボタンを押す

終了すると、iPhone と PC の両方で、その回の解析データは破棄されます。

## 6. GitHub Actions の「Run workflow」操作（iPhone アプリの作成）

「Run workflow」は、GitHub が用意する Mac にアプリを作らせる実行ボタンです。

1. Safari（または Chrome）でこのリポジトリを開く
2. 上のタブを横にスクロールして「**Actions**」
3. 左の一覧（スマホでは上の選択欄）から「**iOS ビルド / TestFlight**」
4. 「**Run workflow**」を押す → `release_mode` を選ぶ → 緑の「**Run workflow**」
5. 黄色い丸が回り始めたら実行中です。30〜40 分ほどで緑のチェック（成功）か赤い✕（失敗）になります
6. 実行をタップすると、いちばん下に**日本語の結果の要約**が出ます

`version`（表示バージョン）と `build_number`（ビルド番号）は空のままで大丈夫です。

`cleanup_dev_certs` は、最初からチェックが入っています（そのままで大丈夫です）。GitHub の Mac は実行のたびに開発用証明書「Apple Development: Created via API」を自動作成するため、そのままだと Apple の証明書の上限に達して止まります。この設定がオンだと、このワークフローが自動作成した開発用証明書だけを毎回整理してから作るので、上限エラーが起きません（配布用の証明書や、TestFlight に配信済みのアプリには影響しません）。

## 7. build_only と testflight の違い

| 選ぶもの | すること |
|---|---|
| `build_only` | ビルド、テスト、署名付き IPA の作成まで。**Apple へは送りません**（動作確認用） |
| `testflight` | 上記に加えて、App Store Connect（TestFlight）へ**アップロード**します |

## 8. TestFlight で自分をテスターへ追加する（初回だけ）

1. Safari で [App Store Connect](https://appstoreconnect.apple.com/apps) を開き、アプリを選ぶ
2. 上の「**TestFlight**」→ 左の「内部テスト」の横の「＋」→ グループ名（例：自分）を付けて作成
3. 作ったグループで「テスター」の「＋」→ 自分の名前にチェック →「追加」
4. 「自動配信」がオンになっていることを確認

## 9. iPhone へインストールする

1. App Store で Apple の「**TestFlight**」アプリを入れる
2. Apple から届く招待メールの「TestFlight で表示」を押す（または TestFlight アプリを開く）
3. 「パズルルート」の「**インストール**」を押す

TestFlight のアプリは 90 日で期限が切れます。その前に「Run workflow」（testflight）をもう一度実行してください。

## 10. 接続できない場合の確認項目

- iPhone と PC が**同じ Wi-Fi** につながっているか（iPhone のモバイル通信だけになっていないか）
- PC ビューアーのウィンドウが開いたままになっているか
- iPhone の 設定 →「プライバシーとセキュリティ」→「**ローカルネットワーク**」で「パズルルート」がオンか
- Windows のファイアウォールで「プライベート ネットワーク」が許可されているか
  （許可し忘れたら：設定 → プライバシーとセキュリティ → Windows セキュリティ → ファイアウォールとネットワーク保護 → ファイアウォールによるアプリケーションの許可）
- Mac の システム設定 → ネットワーク → ファイアウォール で、ビューアーの受信接続が許可されているか
- QR の期限（10 分）が切れていないか（PC 画面の「QR コードを作り直す」）
- 6 桁コードを 5 回間違えるとコードが作り直されます。PC 画面の新しいコードを入れてください
- 公衆 Wi-Fi・ゲスト Wi-Fi では端末どうしがつながらないことがあります（自宅の Wi-Fi で試してください）
- VPN アプリを使っている場合は一度オフにしてください

Run workflow が失敗した場合：

- 実行をタップして、いちばん下の「結果の要約」と赤いエラーを確認します
- 「maximum number of certificates」（証明書の上限）→ `cleanup_dev_certs` にチェックが入っているか確認して再実行
- 「Secrets に…が登録されていません」→ Settings → Secrets and variables → Actions に 4 つの値を登録
- 「契約」「agreement」→ App Store Connect の「ビジネス」（契約）で最新の規約に同意
- 「No profiles」「App Group」→ Apple Developer の Identifiers で、2 つのアプリ ID に App Group `group.com.yosiken0421.padguide` が割り当てられているか確認

盤面がうまく読めない場合：

- アプリの「探索の設定」→「盤面サイズ」を自動判定から 6×5／7×6／5×4 に固定してみる
- 色を間違えたマスをタップして直す（直した色の傾向は iPhone 内に保存され、次から使われます）
- 暗闇・ルーレットなどで画面が暗い／変化し続けるときは、ルートを確定しません

## 11. 秘密情報の扱い

- GitHub の **Repository secrets**（`ASC_KEY_ID` / `ASC_ISSUER_ID` / `ASC_KEY_P8` / `APPLE_TEAM_ID`）は、署名と TestFlight へのアップロードにだけ使います
- ワークフローは鍵を Runner の一時フォルダに保存し、**内容をログに表示せず**、処理の最後に削除します
- 秘密情報をソースコード・README・Issue・チャットに貼らないでください
- PC ビューアーの接続トークンもログには出しません

## 構成（開発者向け）

| 場所 | 内容 |
|---|---|
| `ios/PuzzleCore` | 共通ロジック（盤面認識・色分類・消去/落下/連鎖・ビームサーチ・通信データ）と単体テスト |
| `ios/App` | SwiftUI アプリ（画面共有開始、QR / Bonjour 接続、盤面修正、設定） |
| `ios/Broadcast` | Broadcast Upload Extension（フレーム解析 → 確定 → 探索 → 結果送信） |

| `android` | Android 版（盤面に直接矢印を重ねる） |
| `.github/workflows` | `build-ios.yml`（iOS ビルド / TestFlight）、`build-viewer.yml`、`build.yml`（Android） |

- iPhone アプリの Bundle Identifier：`com.yosiken0421.padguide.app`
- Broadcast Extension：`com.yosiken0421.padguide.app.broadcast`
- App Group：`group.com.yosiken0421.padguide`

（App Store Connect に登録済みの ID に合わせています。変える場合は `ios/project.yml` の `PD_BUNDLE_PREFIX` と、Apple Developer サイトの Identifiers を両方変更してください）
